“노트북에 커피를 흘리지 마”라는 지시를 받았을 때 로봇이 노트북만 피하면 충분할까? 주변 휴대전화도 액체에 취약하다. 2026년 **11월 9일 MIT가 소개한** *Flexible Language-Guided Representation Editing for Adaptive Robot Behavior*의 FLEX는 이처럼 말에 명시되지 않은 **사용자의 선호를 경로 계획에 반영할 특징(feature)**으로 바꾸는 접근이다. 원 논문은 10월 20일 arXiv에 제출됐으므로, 이번 소식은 신규 논문 공개가 아닌 연구팀의 공식 소개다.

## 자연어는 '무엇을 고려할지', 시연은 '얼마나 중요할지' 알려준다

기존 reward learning은 로봇의 경로 시연에서 사용자가 원하는 행동을 추정한다. 하지만 같은 시연은 여러 선호를 설명할 수 있다. 예컨대 노트북을 돌아가는 경로가 전자기기를 보호하려는 것인지, 단순히 가까운 장애물을 피하려는 것인지 구별하기 어렵다. FLEX는 **경로의 평가에 쓰이는 특징 집합 Φ와 특징별 가중치 θ**를 구분한다. 자연어 교정은 Φ를 수정하고, 시연은 주어진 Φ에 대한 선호 가중치 θ를 학습하는 데 쓴다.

논문의 경로 보상은 간단히 `Rθ(τ) = θᵀΦ(τ)`로 표현한다. `τ`는 로봇 경로, `Φ(τ)`는 경로가 전자기기·깨지기 쉬운 물체 등에 얼마나 접근했는지 같은 특징, `θ`는 사용자가 그 특징을 얼마나 중요하게 여기는지 나타낸다. **특징 자체가 누락되면 가중치를 아무리 조정해도 의도를 반영하기 어렵다**는 것이 출발점이다.

## ADD → GENERALIZE → MASK로 특징 표현을 고친다

FLEX는 언어 모델을 이용해 세 연산을 순서대로 수행한다. **ADD**는 새 교정에 필요한 특징을 추가한다. “노트북에 흘리지 마”라면 노트북과의 거리를 고려한다. **GENERALIZE**는 이 구체적 특징을 ‘전자기기와의 거리’처럼 더 넓은 범주로 바꾼다. **MASK**는 현재 장면·선호와 무관해진 특징을 제외해 목록이 끝없이 늘어나는 문제를 줄인다.

논문 구현에서 ADD와 GENERALIZE는 언어 모델이 특징 계산 코드를 생성하기도 한다. 따라서 이 단계는 단순한 자연어 문장 분류가 아니라 **계획기의 평가 함수에 들어갈 특징 표현을 바꾸는 작업**이다. 실제 시스템으로 옮길 때는 생성 코드의 검증과 실행 격리가 별도로 필요하다. MIT 소개에서는 세 단계에 약 5초가 걸린다고 설명한다. 이는 고주파 실시간 모터 제어 주기가 아니라 **사용자 피드백을 반영하는 상위 수준 업데이트 시간**이다.

## 실험에서 확인된 것과 확인되지 않은 것

논문은 9×9 격자 탐색과 7-DoF Franka tabletop manipulation 시뮬레이션, 자연스러운 언어 교정과 실물 로봇 시연을 포함한 사용자 연구를 평가한다. 2D 탐색의 일곱 표현 불일치 시나리오에서 FLEX는 세 연산을 모두 요구하는 조건의 정규화 보상 **0.99±0.01**을 기록했다. 같은 조건에서 ADD만 사용하는 ALGAE는 **0.69±0.03**, 직접 전체 특징을 생성하는 unscaffolded baseline은 **0.78±0.03**이었다(논문 Table 1, 평균±표준오차). 이 수치는 **설정된 보상 함수에 대한 평가**이지 실물 로봇의 99% 작업 성공률이 아니다.

MIT의 11월 9일 소개는 커피 운반, 촛불 이동, 볼링공 운반의 가상 시나리오를 설명한다. 논문은 추가로 실물 사용자 연구를 포함하지만, 이 결과만으로 임의의 가정·공장 환경에서 충돌이나 액체 유출이 방지된다고 볼 수 없다. 언어 모델이 일반화한 ‘전자기기’ 범주가 사용자 의도와 다르거나, 인식기가 대상을 놓치면 잘못된 경로가 나올 수 있다.

## 로봇 연구에 주는 의미

실무적으로는 **자연어 교정 → 구조화된 특징 편집 → reward 재추정 → 경로 재계획**을 서로 다른 모듈로 분리하는 설계가 유용하다. ROS 2 시스템에서는 사용자 교정과 특징 변경을 로그로 남기고, 새 특징의 계산 가능성·장면 인식 신뢰도·기존 안전 제약 유지 여부를 테스트해야 한다. 특히 사용자의 선호를 추론하는 모델을 **충돌 회피의 하드 안전 제약**과 혼동하지 않는 것이 중요하다.

## 부록: 배경지식

### Reward feature(보상 특징)

- **정의:** 로봇 경로를 평가할 때 쓰는 측정 가능한 속성이다.
- **예시(설명용, 논문 실험 아님):** 그리퍼가 깨지기 쉬운 유리컵에서 떨어진 최소 거리를 하나의 특징으로 쓴다.
- **이 글에서의 의미:** FLEX는 특징의 가중치만 조정하지 않고 어떤 특징을 계산할지 자체를 수정한다.

### Representation misalignment(표현 불일치)

- **정의:** 사용자가 중요하게 생각하는 속성과 로봇이 내부적으로 표현하는 속성이 서로 다른 상태다.
- **예시(설명용):** 사용자는 액체와 전자기기의 접촉을 피하려는데 로봇은 노트북 한 대와의 거리만 계산한다.
- **이 글에서의 의미:** ADD·GENERALIZE·MASK는 누락·과도한 구체화·불필요한 특징을 각각 다룬다.

### Reward learning(보상 학습)

- **정의:** 사람의 시연이나 피드백에서 어떤 행동이 선호되는지 나타내는 보상 함수를 추정하는 과정이다.
- **예시(설명용):** 두 우회 경로 중 사람이 선택한 경로를 관찰해 거리와 안전 여유의 상대적 중요도를 추정한다.
- **이 글에서의 의미:** 자연어로 특징 집합을 정한 뒤 시연으로 특징 가중치를 학습한다.

### Normalized reward(정규화 보상)

- **정의:** 기준 최악·최선 보상 사이에서 평가값을 0~1 범위로 환산한 지표다.
- **예시(설명용):** 0.9라는 값은 해당 설정의 최선 경로에 가깝다는 뜻이지 90% 성공률이라는 뜻이 아니다.
- **이 글에서의 의미:** 논문 Table 1의 0.99는 2D 시뮬레이션의 정규화 보상이다.
