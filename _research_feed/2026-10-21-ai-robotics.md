로봇 파운데이션 모델이 있어도 새로운 로봇에 적용하려면 데이터 파이프라인, 학습용 GPU, 추론 서버를 직접 구성해야 한다. **Physical Intelligence는 10월 13일 Pi API 베타를 공개해** 이 연결 과정을 관리형 서비스로 제공하기 시작했다.

사용자는 로봇 시연 데이터를 업로드하고, 제공사가 운영하는 인프라에서 π 모델을 파인튜닝한 뒤, 클라우드에 호스팅된 추론 엔드포인트를 로봇 실행 시스템에 연결한다. 최신 모델은 API를 통해 제공되며, 모델 자체를 로컬에 내려받아 구동하는 방식과는 구별된다. 현재는 베타 참여 신청이 필요한 단계다.

## 배포 파이프라인에서 바뀐 부분

공식 발표가 제시한 반복 과정은 **시연 수집 → 모델 파인튜닝 → 실제 로봇 테스트 → 실패 분석 → 추가 데이터 수집**이다. 여기서 API는 학습·서빙 인프라를 담당하지만, 실제 장비의 센서 동기화, 액추에이터 제어, 안전 정지, 실패 원인 진단까지 자동으로 해결해 주는 것은 아니다.

초기 사례로 Almond의 양팔 로봇 Axol이 자체 조립에 쓰이는 spacer의 버 제거 작업을 수행했다. 업체는 Pi API를 활용해 나흘 동안 모델을 반복 개선했다고 소개한다. 또 Actor의 자율 휠로더가 상업 현장에서 자재를 트럭에 적재하는 사례를 제시했다. 두 사례는 서로 다른 하드웨어와 작업에 대한 적용 신호이지만, 동일 조건의 독립 비교 실험이나 범용 성공률은 아니다.

## 클라우드 추론이 남기는 검증 항목

공식 발표는 여러 초기 적용 사례가 클라우드 추론을 사용했으며 일부 환경에서는 **네트워크 연결 문제가 있었다**고 명시한다. 따라서 로봇 시스템에 적용할 때는 모델 정확도와 별개로 카메라 관측에서 행동 수신까지의 왕복 지연, 지연 변동, 연결 끊김 시의 안전한 동작을 시험해야 한다.

특히 빠른 접촉 조작에서는 클라우드 정책 출력이 어느 주기로 도착하는지, 로컬 저수준 제어기가 그 사이에 어떤 상태를 유지하는지, 실패한 action chunk를 어떻게 중단하는지를 분리해야 한다. Pi API 공개는 접근성을 높인 **학습·추론 서비스 변화**이지, 특정 제어 주기나 실시간성·안전 보장을 입증한 결과는 아니다.
