로봇 제어 문제를 사람에 비유하면, **눈치가 빠르고 상황 판단에 능하지만 손재주가 서툰 '전략가(VLM)'**와 **익숙한 작업은 눈 감고도 빠르고 부드럽게 처리하지만, 돌발 상황이나 긴 기억이 필요한 일에는 쉽게 멈춰 서는 '숙련공(VLA/WAM)'**이 각각 따로 존재하는 상황과 같습니다. 둘을 한 팀으로 묶어 일하게 만들려면 전략가의 지시를 숙련공의 손동작으로 번역해 주고 필요한 도구(시각 인식, 메모장 등)를 챙겨주는 **'업무 매뉴얼과 도구함', 즉 정책 하네스(Policy Harness)**가 필수적입니다. 하지만 하네스를 어떻게 짜느냐에 따라 똑같은 모델을 쓰고도 성공률이 수십 퍼센트포인트씩 출렁이며, 조합 가능한 설정만 수천 가지에 달해 기존 연구들은 소수의 경험적 설정에 의존해 왔습니다.

이 문제를 정면으로 다룬 논문 **〈Toward Agentic Robotics: A Large-Scale Study of Harness Design for Robot-Use Agents〉**(2026년 11월 25일 공개, [arXiv:2611.34778v1](http://arxiv.org/abs/2611.34778v1))는 8개 시뮬레이션 벤치마크, 6개 VLM, 15개 VLA/WAM 체크포인트에 걸쳐 **47만 회 이상의 로봇 롤아웃**을 수행하며 효과적인 하네스 설계 원칙과 가중치 수정 없는 통합 레시피 `X-Harness`를 제시합니다.

## 블록 ① 핵심 컨셉

![Policy harness components and 7 controlled design studies](fig1-block1.png)

그림의 왼쪽과 상단 블록은 에이전틱 로봇(Agentic Robot)의 입력부터 출력까지를 구성하는 **모델·도구 조합**과 **7가지 통제 설계 연구(7 design studies)**의 흐름을 보여줍니다. 기존 방식의 가장 큰 병목은 두 진영의 뚜렷한 한계에서 비롯됩니다. VLM 단독 에이전트는 장면 이해는 뛰어나지만 3D 그리퍼 포즈(pose)를 직접 예측할 때 정밀도가 크게 떨어집니다. 반면 VLA나 월드-액션 모델(WAM)은 학습된 태스크에서는 빠르고 매끄러운 제어를 보여주지만, 환경이 바뀌는 도메인 시프트(domain shift)나 여러 단계를 기억하며 풀어야 하는 장기(long-horizon) 추론 태스크에서는 쉽게 실패합니다.

논문이 제안하는 핵심 컨셉은 **`장면 입력 → VLM 정책 코드 및 인식 도구(하네스) → VLA/WAM 또는 3D 제어 출력`**으로 이어지는 연결 구조를 모델 역량에 맞게 적응적으로 설계하는 것입니다. 7가지 통제 실험에서 도출된 흐름은 다음과 같이 직관적으로 정리됩니다.

1. **VLM에서 출발할 때 (Studies 1–4)**:
   - **행동 수준(Action level)**: VLM에게 3D 좌표 포즈를 직접 찍으라고 하기보다, **서브골(sub-goal)과 3D 정책 코드(3D code)**를 짜게 하는 편이 훨씬 정확합니다.
   - **맥락 및 인식 도구(Context & perception tools)**: 비디오 이력, 메모(notes), 바운딩 박스(Grounding DINO, SAM 2), 추적(CoTracker3), 깊이 추정(Depth Anything V2) 같은 도구를 붙여주어 부족한 공간·시간 맥락을 보완합니다.
   - **호출 타이밍(Timing of VLM calls)**: 매 제어 스텝마다 VLM의 응답을 기다리면 제어 루프가 느려집니다. 대신 **VLM이 만든 폐루프(closed-loop) 코드가 VLM 대기 없이(no VLM wait) 스스로 돌게** 해야 합니다.
   - **정책 코드 형태(Policy-code form)**: 정해진 코드 템플릿은 상대적으로 약한 VLM의 실수를 줄이는 데에만 도움이 되며, 강한 VLM에는 오히려 자유도를 주는 편이 유리합니다.
2. **VLA에서 출발할 때 (Studies 5–7)**:
   - **도움이 필요한 지점(Where harnesses help)**: VLA가 잘하는 정밀 제어는 그대로 두고, 기억·추론·도메인 변화처럼 VLA가 취약한 구간에만 하네스를 덧댑니다.
   - **정책 코드 진화(Policy-code evolution)**: 검증 게이트를 둔 **4~8라운드의 코드 진화** 과정을 거치면 정책 코드의 완성도가 크게 올라갑니다.
   - **런타임 개입(Run-time involvement)**: 평상시에는 빠르고 부드러운 하위 정책이 돌다가, **실패 신호(failure signals)가 감지될 때만 VLM이 런타임에 개입해 구출(rescue)**하는 구조가 효과적입니다.

## 블록 ② 세부 구조 및 실험 결과

![8 benchmarks validating takeaway composition with X-Harness](fig1-block2.png)

그림의 오른쪽 타일 영역은 앞서 도출한 7가지 원칙을 **모델 가중치 업데이트 없이(weight-update-free)** 하나로 묶은 레시피 `X-Harness`(단일 VLM 기반 Offline 레시피 및 다중 VLM 기반 Semi-online 레시피)의 검증 결과를 보여줍니다. 총 267개 태스크, 4,000개 이상의 테스트 설정, 55,000회 이상의 태스크 실행(28,000+ H100 GPU-hours, 42B+ VLM 토큰, $120K+ API 비용 규모)을 통해 확인된 주요 정량 수치는 다음과 같습니다.

- **VLABench (49개 태스크)**: `π0.5` 단독 `25.5%` → X-Harness 적용 `68.3%` (**+42.8%p**)
- **RoboMME (16개 태스크)**: `MME-VLA` 단독 `50.0%` → X-Harness 적용 `89.7%` (**+39.7%p**)
- **LIBERO-PRO (40개 태스크)**: `π0.5` 단독 `58.6%` → X-Harness 적용 `95.4%` (**+36.8%p**)
- **RoboDojo (42개 태스크)**: `WALL-OSS-1.0-lite` 단독 `35.0%` → X-Harness 적용 `62.2%` (**+27.2%p**)
- **SimplerEnv (6개 태스크)**: `π0` 단독 `57.5%` → X-Harness 적용 `82.5%` (**+25.0%p**)
- **RoboCasa365 (50개 태스크)**: `Awomo-0.5I` 단독 `64.4%` → X-Harness 적용 `77.3%` (**+12.9%p**)
- **RoboTwin 2.0 (50개 태스크)**: `π0.5` 단독 `76.6%` → X-Harness 적용 `88.6%` (**+12.0%p**)
- **ManiSkill3 (14개 태스크)**: VLA 없이 VLM+하네스만으로 **`89.3%`** 달성

**아직 검증되지 않은 한계(Caveat)**:
- 본 연구의 8개 벤치마크(267개 태스크)는 **모두 시뮬레이션 환경**이며, 제공된 자료 기준 실물 로봇 하드웨어(Real-world)에서의 Sim-to-Real 전이 성능이나 물리적 지연(latency) 특성은 직접 검증되지 않았습니다.
- `X-Harness` 자체는 가중치 재학습이 필요 없지만, 최적의 정책 코드를 탐색·진화(4~8 gated rounds)하고 대규모로 평가하는 과정에는 상당한 VLM API 토큰 및 GPU 연산 비용이 수반됩니다.

## 내 로봇 시스템에 적용할 포인트

- **재학습 전 '하네스 정비' 우선 검토**: VLA 모델이 장기 태스크나 환경 변화에서 실패할 때 곧바로 대규모 데이터를 모아 파인튜닝하기 전에, Grounding DINO·SAM 2·Depth Anything V2 같은 경량 인식 도구와 상태 메모(notes)를 결합한 하네스만으로도 가중치 수정 없이 큰 폭의 성능 향상을 기대할 수 있습니다.
- **VLM은 '상시 조종사'가 아닌 '코드 작성자 겸 비상 구원투수'로 배치**: 제어 루프 안에 VLM 추론을 매번 끼워 넣으면 지연으로 제어가 망가집니다. 평소에는 VLM이 생성한 폐루프 코드나 VLA가 대기 없이 실행되도록 두고, 실패 신호가 발생할 때만 VLM을 호출해 복구하는 하이브리드 구조가 효율적입니다.
- **사용 중인 VLM 체급에 맞춘 코드 자유도 조절**: 모든 VLM에 동일한 프롬프트와 템플릿을 쓰기보다, 추론력이 제한적인 경량 모델에는 정형화된 정책 코드 템플릿을 제공해 오류를 막고, 상위 프론티어 모델에는 서브골과 3D 코드 생성의 유연성을 열어주는 적응형 설계가 유리합니다.
